仍是角色、分支、提交和权限的唯一权威。接口字段以

## 1. 产品定义

WearWise 衣语面向视障和低视力用户，从已经拥有的衣物中推荐三套可解释搭配，
并以可持续的前台语音会话完成选择、替换和穿衣执行。

产品必须同时回答两个问题：

```text
今天穿什么，为什么这套适合我？
接下来先穿哪件，具体怎么做，什么时候算完成？
```

产品不是配色检查器，也不是只有语音外挂的视觉 App。主流程不能依赖辨认图片、
滑动、长按或寻找图形按钮。视觉界面只显示当前阶段、当前衣物、聆听状态和
必要进度。

## 2. 用户与核心价值

目标用户：

- 以读屏和语音为主要交互方式的盲人。
- 需要大字号、高对比度和更少视觉层级但仍能使用触摸的低视力用户。
- 在穿衣时双手被占用、无法操作手机的用户，作为扩展受益人群。

必须满足：

- 不用看屏幕也能完成核心流程。
- 不用点击业务按钮也能做决定。
- 推荐理由不仅描述颜色，还描述场合气质、正式程度和舒适度。
- 穿衣步骤是可执行动作，不是抽象风格描述。
- 网络故障、API 故障或文本 AI 故障不能阻断基础演示。

不被允许的假设：

- 不声称已经完成医学视力分级。
- 不假设视障用户只需要实用、不需要审美和自我表达。
- 不自动判断衣物实际正反，除非用户完成明确校准。
- 不让文本 AI 自由生成关键穿脱动作。
- 不把“识别到商品”表述为“正品已鉴定”。

## 3. 原功能保留

| 原功能 | v1.0 要求 |
|---|---|
| 自由场合搜索 | 语音直接说场合；本地预设和关键词优先，未命中再调用远端 |
| 自动天气 | 作为推荐上下文；不得强制定位，允许演示天气或稍后设置 |
| 我的衣柜 | 本地保存已确认衣物；照片、标签、语音和手动录入并存 |
| 衣物识别 | 返回可编辑建议，用户确认后才能进入推荐 |
| 标签与商品匹配 | 只返回候选和匹配依据，不做正品鉴定 |
| 三套推荐 | 最多三套；每套包含审美摘要、理由、取舍和穿衣顺序 |
| 单品替换 | 只替换同槽位，其他单品锁定，并重新生成说明和穿衣计划 |
| 保存今日方案 | 保存 outfit、衣物 ID、场合、来源、完成进度和时间 |
| Mock/Fallback | 推荐、场合解析和穿衣辅助均有本地降级 |
| 公开网页 Demo | 无登录、强依赖后端或真实 AI，可完成同一条核心闭环 |

## 4. P0 冻结范围

两天内必须完成：

1. 首次启动、系统麦克风和语音识别授权。
2. 持续前台语音会话、自动恢复聆听和错误恢复。
3. 场合采集、本地理解、确认或重说。
4. 表达方向选择：自然、温和、干练。
5. 三套搭配的语音摘要、A/B/C 选择和比较。
6. 方案理由、取舍和换鞋。
7. 确定性穿衣顺序、逐件语音提示、左右声道提示和完成确认。
8. 完成页面、重新开始和本地保存。
9. 上述闭环的离线样例。
10. 可公开访问的网页镜像和公开源码仓库。

P1 仅在 P0 已稳定后进入：

- 实际相机识别衣物特征。
- OCR 标签和商品候选。
- 真实天气 Provider。
- 文本 AI 生成场合策略和搭配解释。
- 自动部署后端。

P2 不在本次范围：

- 后台常驻唤醒词。
- 连续摄像头观察用户穿衣。
- 自动识别衣物正反而不经用户校准。
- 社交、支付、账户体系。
- 医用或行动安全承诺。

## 5. 主流程

```text
App 进入前台
→ 首次请求系统语音权限
→ 说“开始”
→ 说出场合
→ 系统复述理解
→ 说“确认”或“重新说”
→ 说“自然 / 温和 / 干练”
→ 系统朗读三套方向
→ 说“A / B / C”
→ 可继续“理由 / 换鞋 / 开始穿衣”
→ 完成确定性穿衣顺序
→ 说“完成”保存今日方案
→ 说“重新开始”
```

任意业务阶段都可以说：

```text
重听
帮助
停止
返回
```

## 6. 语音状态机

### 6.1 状态

```text
boot
occasion
confirm
intent
outfits
detail
guide
finish
permissionError
listeningError
```

每个状态必须提供：

- 一个系统问题。
- 一个最小口令集。
- 一个成功转移。
- 一个重听路径。
- 一个无法识别时的收敛提示。

### 6.2 聆听规则

- 原生端使用设备端中文语音识别。
- 只在 App 处于前台且语音会话未结束时聆听。
- 助手朗读时停止识别，避免识别自身回声。
- 助手朗读结束后播放固定双音提示，再自动恢复识别。
- 连续识别结果使用一段静音间隔判定一句话结束，建议 0.9–1.2 秒。
- 已提交的一句话必须清空，不能因识别任务重启而重复执行。
- 后台、锁屏或退出页面后立即停止麦克风和识别任务。
- 不在项目、后端、日志或崩溃报告中保存原始录音。
- 录制权限被拒绝时显示可读屏的阻塞说明和系统设置入口。

### 6.3 口令识别

必须支持同义口令，不要求用户背唯一文案：

| 意图 | 最低支持表达 |
|---|---|
| 开始 | 开始、开始吧、我准备好了 |
| 确认 | 确认、确定、对、是的、可以 |
| 重说 | 重新说、不是、换一个、修改 |
| 自然 | 自然、自然可靠、轻松 |
| 温和 | 温和、温和精致、亲切 |
| 干练 | 干练、清晰、利落 |
| 方案 A/B/C | A、B、C、方案A、第一套 |
| 比较 | 比较、区别、有什么区别 |
| 理由 | 理由、为什么、解释 |
| 换鞋 | 换鞋、替换鞋、换一双鞋 |
| 完成 | 完成、穿好了、下一步 |
| 返回 | 返回、后退、回去、上一步 |

低置信度或无法匹配时只复述当前可选口令，不继续猜测。

## 7. 声音与语音体验

### 7.1 语音输出

- 使用短句，每次只问一个问题。
- 首次摘要建议 8–12 秒，详细理由由用户主动触发。
- 不使用未经解释的视觉词，例如“左图”“右侧卡片”。
- 颜色描述同时解释其气质，例如“浅蓝与深蓝形成清楚但温和的层次”。
- 穿衣动作必须包含衣物、身体位置、一个动作和完成条件。
- 失败提示必须说明下一步能说什么，不能只说“出错了”。

### 7.2 声音语义

```text
左侧短音     用户自己的左侧
右侧短音     用户自己的右侧
上行双音     向上、向前或拿起
下行双音     放下、穿入或完成整理
中央和弦     当前步骤完成
聆听双音     现在可以说话
```

左右声道只是辅助，语音必须同时说出“左侧”或“右侧”。设备不支持立体声时，
语音仍能单独完成流程。

## 8. 穿衣顺序

顺序由客户端确定性规则生成，不由文本 AI 控制。

默认顺序：

```text
下装
→ 上装
→ 配饰
→ 鞋
→ 外套
```

强制依赖：

- 鞋必须在脚部和腿部衣物之后。
- 外套必须在内层上装之后。
- 佩戴配饰不能遮挡或干扰正在使用的行动辅助设备。
- 用户返回上一步时不得丢失当前 outfit。
- 换鞋后必须重新计算穿衣步骤。
- 页面不按计时器自动进入下一步，只有用户说“完成”才推进。

## 9. Apple 视觉要求

视觉目标是清晰、克制、有层次，不是堆叠卡片。

- 使用系统字体、系统背景色和动态颜色。
- 支持 Dynamic Type、VoiceOver、Reduce Motion、Dark Mode 和强制高对比度。
- 主界面只保留一个主标题、一个状态提示和一个聆听指示器。
- 不显示解释型长段落；详细信息通过语音提供。
- 可交互区域至少 44×44 pt；但业务主路径不要求点击。
- 使用 SF Symbols 或自绘简洁图形，不依赖图片传达必要信息。
- 动画只用于表示正在聆听、正在说明和步骤切换，不做装饰性连续运动。
- 不用颜色作为唯一状态信号。
- 公开网页视觉与 iOS 保持相同克制程度，手机宽度不得溢出。

## 10. 技术结构

### 10.1 iOS

```text
SwiftUI View
  → AssistantCoordinator
      → VoiceSession
          → SFSpeechRecognizer / AVAudioEngine
      → AVSpeechSynthesizer
      → CuePlayer
      → DeterministicDressingPlanner
  → API Client
      → Local Mock
      → Remote API
```

强制边界：

- View 不处理语音识别、口令路由或穿衣顺序。
- 语音服务不得直接修改页面状态。
- 网络层不得依赖 View。
- 推荐网络失败时回到本地 fixture，并显示来源为 fallback。
- 原生版本禁止静默回退到云端语音识别。

### 10.2 后端

- FastAPI。
- 无状态接口优先。
- 外部 AI、天气和搜索必须可替换。
- 推荐接口必须包含规则 fallback。
- Provider Key 只存在于后端环境变量。
- 日志不得记录原始音频、衣物照片、精确坐标或密钥。

### 10.3 公开网页

- 静态 HTML、CSS、JavaScript 优先。
- 不要求构建工具或账户。
- 必须加载同一份样例语义，明确标记为交互原型。
- 浏览器语音能力不可用时给出真实说明，不伪造成功。
- Web Speech 可能由浏览器使用系统或云服务，必须在披露中说明。

## 11. 数据和接口

推荐请求只包含用户确认后的结构化衣物字段：

```text
id
slot
category
colors
pattern
fit
material
formality_score
warmth_score
user_confirmed
```

禁止在推荐请求中发送：

- 本地照片路径。
- 标签原图。
- 语音录音。
- 精确位置。
- API Key。

共享接口必须先修改 OpenAPI，再修改 sample-data，再通知 iOS，最后联调。
穿衣顺序和语音口令由客户端本地生成，不新增共享必填接口字段。

## 12. 隐私与安全

- 麦克风和语音识别权限只请求一次，并提供用途说明。
- 原生端强制设备端识别。
- 助手朗读时暂停识别，离开前台时立即停止。
- 不保存录音、连续语音转写或唤醒历史。
- 衣物原图保存在设备本地。
- 只有用户明确触发图片分析时上传临时压缩图。
- 临时图片不得保存或用于训练。
- 天气定位只在用户启用时使用粗略位置，不建立轨迹。
- 商品 URL 只允许 HTTPS，并防止 SSRF。

## 13. 测试要求

### 13.1 自动化

- 口令状态机覆盖所有 P0 状态。
- 覆盖应识别、同义口令、未知口令和静音结束。
- 覆盖助手朗读结束后恢复识别。
- 覆盖重复识别结果不会重复执行。
- 覆盖 A/B/C、比较、返回、换鞋。
- 覆盖四步穿衣、上一步和完成。
- 覆盖推荐接口失败后的 fallback。
- 覆盖 OpenAPI 样例与客户端 fixture 一致。

### 13.2 真机

使用实体 iPhone 连续完成三次：

```text
开始
第一次去女朋友家吃饭
确认
自然
A
换鞋
开始穿衣
完成 × 4
重新开始
```

还必须测试：

- 扬声器播放时不会自己触发“完成”或“确认”。
- 环境噪声不会触发错误状态。
- 耳机、扬声器和蓝牙音频下都能听清聆听提示音。
- App 切后台后麦克风停止，回前台后可恢复。
- 拒绝麦克风时可读屏并进入系统设置。
- 屏幕锁定、低电量模式和充电时仍可演示。
- 左右声道提示在实际设备上能区分。

### 13.3 可用性

至少让一名不熟悉口令的人体验一次。观察是否需要提示、是否把系统语音误认为用户输入、
以及是否能理解“什么时候算完成”。发现阻断问题时缩短句子，不增加按钮。

## 16. 回报与完成标准

每次交付必须报告：

```text
负责人：
分支：
Commit SHA：
完成模块：
运行设备：
测试命令：
真机口令：
实际结果：
截图或录屏：
当前状态：
已知风险：
```

“代码已生成”“AI 说通过”或“看起来没问题”不算完成。完成必须同时满足：

- 有真实 Commit。
- 自动测试通过。
- 有实际请求、真机口令或可访问 URL。
- 共享接口已同步 OpenAPI 和 sample-data。
- 不包含秘密、录音、个人照片或构建产物。
- `docs/build-status.md` 有证据。

## 17. 需求优先级与变更

P0 冻结后，只有以下问题可以插入：

- 构建失败。
- 麦克风或语音识别无法启动。
- 核心流程无法完成。
- 公开 Demo 或提交链接不可用。
- 隐私或安全阻断。

新增视觉细节、额外页面、后台唤醒词或新 Provider 一律推迟到 P1/P2。
改变 P0 需要 iOS 负责人、产品负责人和集成协调人共同确认。

## 18. 唯一事实来源

发生冲突时按以下顺序：

```text
1. CONTRIBUTING.md          角色、权限、分支和流程
2. 本文件                    产品范围、语音体验和验收
3. specs/openapi.yaml       接口字段和错误结构
4. specs/examples/sample-data.json
                             固定样例内容
5. design/page-flow.md      页面状态和交互行为
6. docs/build-status.md     当前进度，不是接口事实
```

聊天记录、AI 临时建议和未提交代码不能覆盖以上文件。
