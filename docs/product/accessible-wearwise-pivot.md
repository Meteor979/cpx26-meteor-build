# WearWise 无障碍穿搭方向

## 1. 核心命题

WearWise 为视障用户提供一套可以独立完成的穿搭闭环：

```text
说出今天要做什么
→ 听见三套适合且彼此不同的搭配
→ 选择自己想表达的感觉
→ 按声音提示逐件穿衣
→ 完成并保存今天的状态
```

这是一套语音驱动产品，不是带语音按钮的视觉 App。主流程不要求触摸、滑动、
长按或辨认图形按钮。屏幕只保留当前阶段、当前衣物和聆听状态等必要信息，
操作由持续麦克风和短口令状态机完成。

产品不是替视障用户决定“什么好看”，而是把颜色关系、正式程度、场合语气、
舒适度和个人偏好转换成可以听、可以重复、可以理解的选择。

这一版本面向视障和低视力用户，同时保留 VoiceOver、大字号、高对比度和
键盘操作，不以“看得见”为前提。

## 2. 用户问题

现有穿搭产品通常把最重要信息放在图片里，默认用户能够：

- 辨认衣物并判断颜色是否协调。
- 看懂整套搭配的整体气质。
- 知道衣服的前后、左右和穿脱顺序。
- 在穿衣卡住时再次查看视觉提示。

视障用户真正缺少的不只是推荐结果，而是从“决定穿什么”到“把衣服穿好”的
连续支持。WearWise 因此需要同时解决决策和执行。

## 3. 三条核心体验

### 听见审美

每套搭配先给一句 8–12 秒的整体听感，例如：

> 方案 A，清晰、自然、不过分正式。浅蓝上装和深蓝下装形成容易辨认的层次，
> 白鞋让整体更轻松，适合第一次家庭聚餐。

用户需要时再听颜色关系、正式程度、社会语气、天气舒适度和取舍。
颜色不能单独承担含义，所有颜色描述同时说明它造成的感觉。

### 听见位置

左声道对应用户自己的左侧，右声道对应右侧，中央声音用于确认正面和完成。
声音承担主要导航；必要状态文字只用于低视力用户、调试和辅助技术，
不要求用户在屏幕上找到并点击控件。

基础声音语义：

| 声音 | 含义 |
|---|---|
| 左侧短音 | 注意左侧衣袖、裤腿或鞋 |
| 右侧短音 | 注意右侧衣袖、裤腿或鞋 |
| 上行双音 | 向上、向前或拿起衣物 |
| 下行双音 | 放下、穿入或完成整理 |
| 中央和弦 | 当前步骤完成 |

### 听见步骤

确认搭配后，系统根据实际衣物生成穿衣顺序，并把每一步拆成：

```text
物品名称
→ 身体位置
→ 一个动作
→ 一个完成条件
→ 可重复的声音提示
```

默认安全顺序：

```text
下装
→ 上装
→ 配饰
→ 鞋
→ 外套
```

依赖规则始终优先：

- 鞋必须在对应的脚部衣物之后。
- 外套必须在上装之后。
- 配饰不能插入用户当前正在完成的穿脱动作。
- 用户可暂停、重听、返回上一步或调整步骤，但系统提示依赖关系。

AI 可以解释搭配，不直接决定关键穿衣动作。基础顺序和提示由确定性规则生成，
避免网络故障或模型幻觉阻断真实穿衣过程。

## 4. 原功能保留

| 原功能 | 新方向 | 处理 |
|---|---|---|
| 自由文本场合搜索 | 支持键盘、语音输入和预设 | 保留 |
| 自动天气 | 作为推荐上下文，也可使用演示天气或手动城市 | 改造为可选 |
| 衣柜管理 | 照片识别、标签匹配和语音/手动录入并存 | 保留 |
| 衣物识别 | 识别结果朗读并逐项确认 | 保留 |
| 三套搭配 | 每套包含听感摘要、理由和取舍 | 保留并扩展 |
| 替换单品 | 替换后重新生成理由和穿衣顺序 | 保留 |
| 保存今日方案 | 保存穿搭与完成进度 | 保留 |
| Mock/Fallback | 推荐和穿衣辅助均可离线运行 | 保留 |
| 公开网页 Demo | 演示完整语音与声音引导闭环 | 保留 |

## 5. 交互原则

1. 所有主流程操作都有明确的口令，不要求触摸或识别图形按钮。
2. 不强制定位；用户可以选择自动天气、演示天气或稍后设置地点。
3. 每次只问一个问题，每段说明后自动恢复聆听，并使用短提示音标记开始。
4. 助手说话时暂停识别以避免回声；说明结束后自动重新进入持续聆听。
5. 背景音、口语和自我打断不能被误当成“确认”或“完成”。
6. 持续聆听只在产品位于前台且当前会话未结束时开启，并提供明确状态。
7. 不使用“左图右文”一类依赖视觉方位的说明。
8. 不做“正版鉴定”等超出证据的结论。
9. 对 AI 结果明确说明来源和不确定项。

## 6. 语音状态机

| 阶段 | 系统提问 | 用户口令 |
|---|---|---|
| 启动 | “说开始” | `开始` |
| 场合 | “今天去哪里” | 自由说出一个场合 |
| 理解确认 | “这样理解吗” | `确认` / `重新说` |
| 表达方向 | “想给人什么感觉” | `自然` / `温和` / `干练` |
| 三套搭配 | “说A、B、C或比较” | `A` / `B` / `C` / `比较` |
| 方案确认 | “开始、理由、换鞋或返回” | 对应口令 |
| 穿衣步骤 | “完成后说完成” | `完成` / `重听` / `左` / `右` / `上一步` |
| 完成 | “重新开始” | `重新开始` / `查看方案` |

任意阶段都可说`重听`、`帮助`、`停止`。系统必须对无法识别的短句给出一个
更小的选择集，不能连续朗读帮助后继续猜。

### 聆听生命周期

```text
前台打开
→ 首次请求系统麦克风/语音识别权限
→ 助手说明
→ 聆听提示音
→ 持续识别
→ 检测到一句结束
→ 暂停识别
→ 执行口令并说明
→ 再次聆听
```

原生 iOS 版本优先使用设备端语音识别，不保存或上传录音。浏览器公开 Demo
受 Web Speech 实现限制，只能保证应用自身不保存音频；是否使用浏览器语音服务
必须在披露文件中写清楚。

## 7. 首要演示闭环

```text
进入产品并首次允许麦克风
→ 说“开始”
→ 说出“第一次去女朋友家吃饭”
→ 说“确认”
→ 说“自然”
→ 听见三套搭配的方向差异
→ 说“A”
→ 说“换鞋”
→ 说“开始穿衣”
→ 说“完成”完成下装、上装、鞋和外套
→ 保存已完成
```

公开网页必须在不登录、不依赖后端和真实 AI 的情况下完成这条路径。

## 8. 两天内不做什么

- 不声称根据医学视力等级自动改变推荐。
- 不依赖手机持续摄像头观察穿衣过程。
- 不自动判断衣物实际正反，除非用户明确完成校准。
- 不建立精确身体尺寸、面部或位置画像。
- 不让文本 AI 自由生成安全关键动作。

## 9. 演示前的验证假设

这些假设必须通过与视障用户交流或至少一次可用性测试验证：

- 用户更愿意先听整体听感，再决定是否听详细理由。
- 左右声道提示比单调提示更容易建立方向感。
- 穿衣步骤应允许随时暂停和重听。
- “场合语气”比单纯“正式/休闲”更接近用户真实的穿搭决策。
- 自动恢复聆听比要求用户每个步骤再次启动麦克风更自然。
