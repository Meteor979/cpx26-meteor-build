# WearWise 色觉与低视力穿搭方向

## 1. 核心命题

WearWise 面向色盲、色弱和低视力用户，解决他们“看不清衣物细节、难以判断颜色
关系、不知道怎么把已有衣服搭在一起”的问题。

```text
拍摄已有衣物
→ 建立自己的照片衣柜
→ 说出或选择场合
→ 获得三套可解释搭配
→ 查看每套搭配中的真实衣物照片
→ 调整、确认和保存
```

产品不尝试服务全盲用户。全盲用户无法完成拍照建柜这一核心入口，不是本次目标。
VoiceOver 和可选语音说明继续保留，但视觉图形界面和触摸操作是主路径。

## 2. 用户问题

色盲和色弱用户通常能够看见衣物和界面，但难以可靠判断：

- 两种颜色是否属于同一色系。
- 整套搭配是否协调。
- 某件衣服适合正式还是休闲场合。
- 图案、材质和层次是否冲突。

低视力用户还可能需要：

- 更大的文字、图片和按钮。
- 黑白高对比度，而不是低对比度彩色卡片。
- 更少的界面层级和更明确的焦点。
- 不依赖颜色区分选中、禁用和错误状态。

用户已经拥有衣物，并能拍摄照片。产品必须尊重这些照片是推荐结果最直观、
最可信的视觉证据。

## 3. 产品原则

### 3.1 黑白高对比

- 主界面采用黑白灰设计。
- 选中态同时使用描边、填充、勾选图标和文字，不能只用颜色。
- 成功、警告和错误状态必须同时有图标与文字。
- 图片周围使用稳定边框，避免不同衣物照片的亮度影响页面结构。
- 允许系统暗色模式，但两种模式都必须满足高对比度。

### 3.2 图形按钮重新成为主路径

- 所有业务操作都有清晰、可见、可点击的图形按钮。
- 关键按钮高度至少 56 pt，图标和文字同时出现。
- 图标不能单独承担含义。
- 按钮支持键盘和 VoiceOver，但不再以提高触摸成本为设计目标。
- 界面最多保留两级主要信息：当前动作和当前内容。

### 3.3 照片属于衣柜，也属于结果

- 用户添加衣物时保留一张本地主图。
- 推荐结果必须从用户上传的主图生成视觉搭配，不调用无关商品图代替。
- 三套搭配都展示真实衣物图片，不显示纯文字搭配。
- 图片缺失时显示带衣物名称的占位框，不能静默隐藏衣物。
- 原图保存在设备本地；推荐接口仍只传结构化衣物字段。

### 3.4 审美可解释

每套搭配需要同时提供：

- 整体气质，例如自然、温和、利落。
- 颜色关系，例如同色系、明暗对比或冷暖对比。
- 正式程度和场合适配。
- 舒适度、天气和行动便利性。
- 一处需要接受的取舍。

颜色名称必须配关系解释。只说“蓝色配灰色”不够，还要说明“明暗差稳定，
看起来清楚而不过分正式”。

## 4. 核心流程

```text
首页
→ 选择场合与表达方向
→ 检查可用衣柜
→ 生成三套搭配
→ 以衣物照片组成的卡片展示三套结果
→ 查看一套的理由与取舍
→ 替换一件同槽位衣物
→ 确认并保存
```

衣柜入口始终可用：

```text
我的衣柜
→ 添加上装、下装、鞋或外套
→ 拍摄衣物主图
→ 快速识别或标签匹配
→ 用户审核属性
→ 保存到本地衣柜
```

## 5. 原功能保留

| 原功能 | 处理 |
|---|---|
| 自由场合搜索 | 保留，增加大尺寸搜索框、预设按钮和可选语音输入 |
| 自动天气 | 保留，作为推荐上下文；允许使用演示天气 |
| 我的衣柜 | 完整保留，增加照片列表和明确的添加入口 |
| 图片识别 | 保留，结果由用户审核后保存 |
| 标签和商品匹配 | 保留，不改变“候选而非正品鉴定”的规则 |
| 三套推荐 | 保留，新增真实衣物图片拼贴 |
| 推荐理由和取舍 | 保留，强化颜色关系与场合解释 |
| 替换单品 | 保留，更新搭配图片、理由和穿衣顺序 |
| 保存今日方案 | 保留 |
| Mock/Fallback | 保留 |
| 声音辅助和穿衣顺序 | 保留为可选增强，不是进入流程的前置条件 |
| 公开网页 Demo | 保留，必须展示真实样例照片和黑白图形按钮 |

## 6. 图形界面要求

- 使用 Apple 风格的清晰层级和系统字体，但将按钮、卡片与焦点做得更醒目。
- 主页面使用黑白背景、边框和字重建立层次，不依靠低饱和色块。
- 推荐卡片顶部最先显示衣物照片组合，其次显示搭配名称。
- 图片比例统一，衣物主体不因裁剪而消失。
- 按钮包含图标和动词，例如“添加衣物”“生成搭配”“替换鞋子”。
- 不使用颜色作为唯一选中信号。
- 不要求用户长按、精细拖拽或识别很小的图标。
- 字体支持 Dynamic Type；关键内容至少支持 200% 缩放。
- 支持 Reduced Motion，避免图片和卡片跳动。

## 7. 声音辅助边界

声音继续用于：

- 朗读场合理解。
- 解释颜色和搭配理由。
- 可选穿衣步骤。
- 听写场合或辅助输入。

声音不再要求：

- 持续麦克风常开。
- 整个流程仅靠口令完成。
- 使用前后声道完成所有导航。
- 隐藏图形按钮。

麦克风只在用户主动开启语音辅助时工作，并明确显示聆听状态。

## 8. P0 演示闭环

```text
打开 App
→ 进入照片衣柜
→ 选择或添加衣物
→ 输入“第一次去女朋友家吃饭”
→ 查看场合理解
→ 进入三套推荐
→ 三套卡片均显示用户衣物照片
→ 打开方案 A
→ 解释颜色、场合和取舍
→ 替换鞋
→ 确认保存
```

公开网页可以用样例衣柜图片完成同一流程，不要求登录或真实 AI。

## 9. 验收假设

需要通过至少一次可用性测试确认：

- 用户能在不依赖颜色状态的条件下操作界面。
- 用户能理解三套搭配的视觉差异和文字解释。
- 用户能看出推荐使用的是自己衣柜里的衣物。
- 添加衣物照片的路径足够清楚。
- 在 200% 字号或常见低视力设置下，主要按钮和结果卡片仍可使用。

## 10. 不在本次范围

- 全盲用户的拍照建柜流程。
- 自动识别衣物正反。
- 依赖摄像头持续观察用户穿衣。
- 医用色盲矫正或诊断。
- 使用商品图替换用户衣柜照片。
- 声称 AI 可以确定用户看到的颜色。
