# WearWise Backend

Backend service for WearWise. The current milestone implements health, occasion
context, rule-based recommendation, outfit revision, and weather context with
deterministic Mock data. It does not call external services in the default mock
configuration. An optional server-side text AI provider can enhance occasion
resolution and outfit explanations.

## Requirements

- Python 3.9+
- Windows PowerShell
- macOS/Linux shell

## Python compatibility

The backend supports Python 3.9 and newer. Do not use Python 3.10-only syntax
such as `X | None`, `int | None`, or union expressions in public models. Use
`Optional`, `List`, `Dict`, and `Tuple` from `typing` instead. Recreate the
virtual environment after changing the Python version.

## Current endpoint

`GET /health` returns:

```json
{
  "status": "ok",
  "timestamp": "2026-11-21T10:00:00Z",
  "providers": []
}
```

The response schema follows [`specs/openapi.yaml`](../../specs/openapi.yaml).
No API keys or `.env` file are required for this milestone.

## Context Mock endpoints

```powershell
curl.exe -i "http://127.0.0.1:8000/v1/presets?limit=4"

curl.exe -i -X POST "http://127.0.0.1:8000/v1/occasions/resolve" `
  -H "Content-Type: application/json" `
  -d '{"query":"第一次约会","locale":"zh-CN"}'
```

The presets endpoint returns the four fixed policies from
`specs/examples/sample-data.json`. The occasion resolver performs local
normalization, exact name/alias matching, and deterministic keyword matching.
Unknown queries receive a low-confidence fixed fallback.

## Recommendation Mock endpoints

```powershell
curl.exe -i -X POST "http://127.0.0.1:8000/v1/recommendations" `
  -H "Content-Type: application/json" `
  --data-binary "@examples/recommendation-rule-request.json"

curl.exe -i -X POST "http://127.0.0.1:8000/v1/outfits/revise" `
  -H "Content-Type: application/json" `
  --data-binary "@examples/outfit-revision-rule-request.json"
```

The recommendation endpoints return deterministic rules with
`provider=rule_engine_mock`, `fallback_used=true`, and an explicit warning. They
return only stable garment IDs and never include local photo paths or image URLs.

## Weather context

`POST /v1/weather/current` accepts coarse coordinates, accuracy, timezone, and
an optional target time. It uses `MockWeatherProvider` until a live provider is
configured.

```bash
curl -i \
  -X POST \
  http://127.0.0.1:8000/v1/weather/current \
  -H "Content-Type: application/json" \
  --data-binary @examples/weather-request.json
```

The response:

- Uses English warning text and `source: "mock"`.
- Returns structured temperature, feels-like temperature, condition,
  precipitation probability, and wind speed.
- Never echoes latitude or longitude.
- Does not persist coordinates.
- Returns `status: "unavailable"` and `weather: null` if the provider fails.

Weather is optional to the client. A weather failure must not block
recommendations; the iOS client should use a recent cache or demo weather.

## Optional text AI

The API defaults to deterministic local rules:

```text
TEXT_AI_PROVIDER=mock
```

With `mock`, no external model is contacted. Local exact/alias matching runs
before occasion fallback, and recommendations remain rule-generated.

To enable an OpenAI-compatible chat-completions provider:

```text
TEXT_AI_PROVIDER=remote_api
AI_API_KEY=<server-side secret>
AI_BASE_URL=<provider base URL>
AI_MODEL=<model name>
AI_TIMEOUT_SECONDS=20
```

Remote AI may only:

- Generate a structurally validated occasion policy when local matching misses.
- Rank and explain legal outfit candidates generated by the deterministic rule
  engine.
- Rewrite title, reasons, and tradeoffs after a validated same-slot revision.

The server rejects invented garment IDs, duplicate items, invalid slots, and
malformed JSON. Any provider error, timeout, invalid response, or missing
configuration falls back to local rules. API keys and raw provider responses
never reach the client.

Do not commit `.env`, credentials, recordings, personal photos, or generated
build output.
